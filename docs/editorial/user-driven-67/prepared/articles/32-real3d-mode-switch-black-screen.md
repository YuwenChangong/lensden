# REAL 3D Goes Black but Ultrawide Works: Keep the Mode-Switch Evidence

A [One Pro owner using Samsung DeX](https://www.reddit.com/r/Xreal/comments/1rhfjfe/) reports a black screen when switching REAL 3D on or off, while describing different behaviour for ultrawide. A suggested workaround involving leaving DeX did not solve the original owner's issue. Preserving that reply matters: it prevents an unconfirmed suggestion from becoming a published fix.

The discussion identifies a Samsung Fold workflow but does not establish a complete phone OS, glasses firmware and accessory matrix. Lensden has not reproduced it. A later firmware release or a different Fold generation may behave differently.

## Capture the transition

Record whether the problem occurs entering the mode, leaving it or both. Note whether the glasses menu remains visible, whether audio continues and whether the host still detects the display. A transition failure is a different observation from a file that never plays correctly in an already active 3D mode.

Use an ordinary non-sensitive source and the documented direct connection first. Do not change DeX options, output resolution, power accessories and glasses mode simultaneously. Keep an accessible conventional screen so the host remains controllable if the glasses image disappears.

## Separate the features

[XREAL's REAL 3D page](https://tutorials.xreal.com/docs/glasses/one-series/osd/real-3d/) describes conversion of 2D material. A pre-existing side-by-side 3D file is a different input. Ultrawide is another distinct mode. Success in one does not establish that the others negotiate the same output with the phone.

Likewise, screen stabilisation and visible content cadence need separate observations. A smooth device menu does not prove the converted video is smooth. A black image does not establish that a particular conversion chip has failed.

## Share the negative result too

If a supported troubleshooting step does not help, record that once rather than repeating it indefinitely. Include the exact before-and-after sequence in the support request. Do not recommend enabling unrelated developer features or downloading unofficial firmware as a routine solution.

For a purchasing decision, ask whether the required DeX and mode combination is supported on the exact phone, rather than buying a hub because someone else's reply mentions power. [Lensden's coding guide](/guides/ar-glasses-coding-virtual-monitors/) keeps desktop presentation separate from additional monitors.

This account provides a reproducible question, not a universal incompatibility finding or a verified remedy. Source review: November 3, 2026. No Lensden hands-on test or claim that current firmware retains the historical behaviour.
