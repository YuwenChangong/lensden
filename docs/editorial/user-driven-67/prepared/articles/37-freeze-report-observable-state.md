# A Frozen Last Frame Is Different From No Signal: Write the Support Report That Way

An [XREAL One Pro owner report](https://www.reddit.com/r/Xreal/comments/1ld7kc1/how_often_does_your_xreal_one_pro_freeze/) describes a static last image and unresponsive controls shortly after connection, across several sources. The writer compares the symptom to corrupted memory, but does not establish that cause. A support reply asks the owner to contact the vendor for assessment.

The phrase “it freezes” hides several possibilities. The source application may have stopped, the connection may have disappeared, or an image may remain visible while the device stops accepting controls. A useful report describes what can still be observed without pretending to diagnose the internal failure.

## Preserve the state before restarting

If it occurs during ordinary use, note whether audio continues, whether the source still identifies an external display and whether the glasses' own documented controls respond. Record the last action before the symptom. Do not keep repeating a failing session merely to count crashes, and stop for flicker or discomfort.

Use a harmless sample page or clip when documenting the behaviour. A video of a confidential desktop can disclose more than support needs. If a through-lens recording cannot clearly capture the symptom, explain that limitation instead of editing it to look more dramatic.

## Keep participant outcomes separate

The discussion includes suggestions involving cables, sleep settings and resets, and a participant who reports improvement after contacting support and resetting. These are different owners' experiences. They do not establish a universal fix or the original author's final outcome.

The [manufacturer's black-screen guidance](https://tutorials.xreal.com/docs/glasses/one-series/troubleshooting/blackscreen/) offers a reference for a different but related symptom. Use the applicable section and exact model. A last frame remaining visible should not simply be relabelled a black screen to fit an available checklist.

## Send a short sequence

A compact support note can contain the model, source, firmware if known, connection chain, steps before failure, remaining image or audio, control response and any supported comparison already made. State which values are Unknown rather than calling an unspecified build the latest version.

Keep receipts and the return deadline available if assessment or replacement is proposed. Opening the device or installing unofficial firmware to prove an online theory creates additional uncertainty.
