## Fail-Closed Operation

The fixed project/login/role and Session Pooler5432 endpoint are immutable module
constants. Exactly seven reviewed statements are extracted from hash-verified
bytes; the public transport exposes numbered steps, not arbitrary SQL. Socket and
startup guards reject a second connection/authentication before dispatch. The
startup packet is reconstructed from fixed user/database/UTF8/application fields;
ambient PostgreSQL startup options cannot change it. No pool, SET ROLE, migration,
fallback credential source, retry or automatic query expansion exists.

Native transport creation requires a one-time in-memory permit issued only after
exact owner/review authorization validation, verified sink and durable exclusive
authorization consumption. A direct native-factory call cannot obtain a permit.
Offline fixture authorization has a different schema/review tag and cannot run
through the Production authorization path. No valid Production record is present
or generated by tests. Importing or directly running these modules does not connect.

with CA/date checks, peer validation, hostname verification and no fallback. The
current task reads no actual CA/password and performs no handshake. Future

lookups, files, command arguments or chat. JS strings cannot promise secure memory

Budgets: connect10s, statement8s, lock1s, idle transaction15s, overall30s including
admission, persistence and cleanup. One monotonic deadline reserves4s for cleanup;
per-step budgets can only shrink. Result/sink operations receive revocable budget
capabilities checked between asynchronous filesystem steps, preventing a timed-out
chain from starting later writes. Already-issued OS I/O cannot be forcibly undone;
late/failed persistence and uncertain client closure remain BLOCKED, never PASS.
Cleanup waits for end/TCP/TLS close observations within the same budget, not merely
successful destroy/end calls. The first sanitized failure is never overwritten.

Result validation has exact top-level, identity, section and per-row key/type
sets; caps match the SQL. Unknown fields, missing sections, identity drift,
truncation, incomplete columns/ownership coverage, ACL excess, oversized records,

query caps do not replace the client limits. Errors expose only allowlisted codes
or SQLSTATE, not messages, stacks or catalog contents.
