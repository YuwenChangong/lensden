## 这份清单用于什么

这份页面用于记录 Lensden 在正式进入搜索引擎监控前需要完成的最小动作。它不依赖付费 SEO 工具，重点是把页面发现、索引确认和重点 URL 提交做扎实。

## 1. Property 设置

- 打开 Google Search Console
- 当前 workers.dev 地址使用 `URL prefix`；不要验证不属于你的共享父域名
- 当前生产地址使用 `https://lensden.ogh.workers.dev`
- 如果后续切换独立域名，需要重新补做域名级验证或新增 property

## 2. Sitemap 提交

- 站点上线后确认 `https://lensden.ogh.workers.dev/sitemap-index.xml` 可访问
- 索引中的 `/sitemap.xml` 提供 SSR 动态页面；不要只检查构建生成的固定页面清单
- 在 Search Console 的 `Sitemaps` 页面提交该地址
- 等待 Google 抓取并记录成功、失败或警告状态

## 3. 首批手动检查 URL

建议优先用 `URL Inspection` 提交以下页面：

- `/`
- `/products/`
- `/guides/`
- `/guides/ar-ai-glasses-buying-guide-2026/`
- `/guides/ar-ai-xr-glasses-difference/`
- `/guides/best-ar-ai-glasses-for-developers/`
- `/guides/why-most-ar-glasses-cannot-run-custom-os/`
- `/feed/`

旧 `/devices/` 是跳转入口，不作为产品详情的规范地址提交。Gaze Launcher 公开开关仍关闭时，不提交该页面。产品详情只选择已发布且可匿名访问的真实 `/products/{brand}/{slug}/` URL。

## 4. 预期验证步骤

- 页面能返回 200 状态
- 页面使用生产域名 canonical
- 页面 title 与 description 已输出
- sitemap 中能看到对应 URL
- robots.txt 可访问且未屏蔽关键内容页
- 页面没有明显 broken links

## 5. 常见异常

- 新页面未被发现：通常是内部链接不足或 sitemap 尚未重新抓取
- 页面未编入索引：可能是内容过薄、重复或 Google 认为价值不足
- canonical 异常：需要优先检查配置中的 `site`

## 6. 建议的 30 天观察节奏

- 第 1 周：确认 sitemap 提交成功，重点 URL 已请求索引
- 第 2 周：查看哪些页面开始进入索引
- 第 3 周：检查高价值 guide 和 devices 页是否被发现
- 第 4 周：根据展示量、点击量和未索引原因做内容补强

## 7. AI 搜索记录

分别记录 Google Web 总展示与 Generative AI Search/Discover 报告中的展示；AI 数据与总量有重叠，不要相加。Google 的 [2026 年 6 月官方公告](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports) 介绍了独立报告。没有权限、没有数据或报告不可见时记录未知，不填零。Bing Webmaster Tools 的 AI Performance 引用次数与访问次数也应分开。本站是否完成验证、已被索引、获得 AI 引用仍需由站点所有者实际确认，本清单不表示这些动作已经完成。
